# 146. LRU 缓存

[力扣原题](https://leetcode.cn/problems/lru-cache/) · 中等 · [本类目录](../README.md) · [总目录](../../README.md)

## 要解决什么

实现容量有限的缓存，get 和 put 平均 O(1)，满时淘汰最久未使用项。

## 怎么想到这个方法

**哈希表定位 + 双向链表维护新旧**

双向链表头部存最近使用的键值对，尾部存最久未使用项。哈希表从 key 定位到链表迭代器，查询命中或更新已有键时，用 splice 把节点移到头部。插入新键前若容量已满，删除尾节点并同步删掉哈希表条目。两种结构各负责一个问题：快速找到节点，以及快速修改使用顺序。

## 跟着例子走一遍

容量 2，依次 put(1,1)、put(2,2)、get(1)，顺序变为 1、2。再 put(3,3)，淘汰尾部的 2，因此 get(2) 返回 -1。

## 写代码时注意什么

更新已有键不能误增缓存数量。删除链表节点前先删除表中的键，避免悬空迭代器。缓存对象不提供拷贝操作，因为默认拷贝会使迭代器指向另一个对象的链表。

## 复杂度

- 时间：get、put 平均 O(1)。
- 空间：O(capacity)。
